## Getting started

### What you need {#requirements}

Windows 10 version 2004 or later, or Windows 11, on an x64 PC. ARM64 builds aren't available yet.

### Install

<Steps>

1. Download <a href={links.download}><code>Zinc-win-Setup.exe</code></a>, the latest build.
2. Run it. It installs Zinc for your user only, so it doesn't ask for administrator rights.
3. If Windows SmartScreen stops it, choose **More info**, then **Run anyway**.

</Steps>

<Warning title="Alpha builds aren't signed yet">
That's why SmartScreen asks. Signing is coming, and once signed builds have earned SmartScreen's trust, it stops asking.
</Warning>

Rather not install? <a href={links.downloadPortable}><code>Zinc-win-Portable.zip</code></a> holds the same build in a folder you can run from anywhere.

### Updates

Installed copies check for a new build once a day and update themselves. You'll find the version you have, and the option to check now, in `Settings > About > Updates`. What changed is in the [changelog](/changelog).

### First launch

The first time Zinc starts, a welcome page asks how you like to work and saves your answers to your settings. Reopen it any time with **Welcome…** in the command palette (<kbd>Ctrl+Shift+P</kbd>). It changes only what you change there.

- **Layout.** Simple, with tabs along the top and one terminal each, or workspaces, in a sidebar or along the top, each with its own tabs and splits.
- **Panes.** Compact, edge to edge, or cards, each with a header and a gap around it.
- **Color scheme and font**, with a preview. Pick one scheme, or a pair that follows Windows' light and dark mode.
- **Default shell.** Zinc lists the shells it found on your PC.
- **Notifications.** Whether a long command that finishes in the background shows a Windows notification.

### Keys worth knowing {#keys}

| Action | Keys |
|---|---|
| Command palette: every action, profile, and workspace | <kbd>Ctrl+Shift+P</kbd> |
| Settings | <kbd>Ctrl+,</kbd> |
| Quick terminal, from anywhere in Windows | <kbd>{"Win+`"}</kbd> |
| New tab / new workspace | <kbd>Ctrl+Shift+T</kbd> / <kbd>Ctrl+Alt+T</kbd> |
| Split right / down | <kbd>Alt+Shift+Plus</kbd> / <kbd>Alt+Shift+Minus</kbd> |
| Previous / next prompt | <kbd>Ctrl+Shift+↑</kbd> / <kbd>Ctrl+Shift+↓</kbd> |
| Find in the scrollback | <kbd>Ctrl+Shift+F</kbd> |

Every action and its default keys are in <a href={links.keys}>Keys and actions</a>. Change them in `Settings > Keyboard` or in `[keys]`.

## Configuration

Change settings in the Settings window or in `config.toml`. They're the same settings, so a change in one shows in the other and applies straight away, in every open window.

### The Settings window {#settings-window}

Open it with <kbd>Ctrl+,</kbd>, from the command palette, or from the tray icon. Each change is saved as you make it, and each setting shows its key in the file.

- **Find a setting** (<kbd>Ctrl+F</kbd>) searches settings, keys, and profiles, so "font size ubuntu" finds the font size in your Ubuntu profile.
- **The preview** at the top of Appearance and each profile's page shows your font, colors, and padding as you change them.
- **The reset arrow** beside a changed setting puts it back to its default. On a profile's page, it goes back to what the profile inherits.
- **Undo changes**, at the bottom, puts the file back as it was when you opened the window.

### The config file {#config-file}

Your settings live in `%APPDATA%\Zinc\config.toml`. It's [TOML](https://toml.io), which groups settings into sections and allows `#` comments. Changes apply when you save.

```toml title="config.toml"
default-profile = "wsl:Fedora"

[font]
family = "JetBrainsMono NF"
size = 11                    # points

[colors]
theme = "Dracula"            # a bundled scheme, or one of yours
background = "#181818"       # single colors override the scheme

[window]
workspace-tabs = "left"

[profile."wsl:Fedora"]
name = "Fedora"
command = 'wsl.exe -d Fedora --cd ~'
colors.theme = "0x96f"
```

<Note title="A mistake doesn't stop the rest">
Zinc shows a bar with the file and line of anything it can't read, and applies everything else. Until you fix it, the Settings window doesn't save. Single-quoted strings are literal, so Windows paths need no escaping: `'C:\msys64\ucrt64.ico'`. If the file isn't valid TOML at all, Zinc keeps the settings it had.
</Note>

Files you `include` and your own color schemes reload when you save them too. To read everything again yourself, run **Reload config** from the command palette.

Your editor can complete keys and catch mistakes as you type, from the file's JSON Schema. Make sure the first line of `config.toml` looks like this, and editors that read schema lines (such as VS Code with Even Better TOML) pick it up:

```toml title="config.toml"
#:schema https://zincterminal.dev/schema/config.json
```

### Color schemes

[Lit Cell and Lit Cell Light](/lit-cell) come with Zinc, along with about 650 schemes from iTerm2-Color-Schemes. Browse them in `Settings > Appearance > Color scheme`, where each one shows in its own colors and a click tries it in the preview. Your own go in `%APPDATA%\Zinc\themes\`, one file per scheme in Ghostty's theme format.

To change a scheme's colors, use the pencil on its card. Editing a bundled scheme changes a copy in your `themes` folder, and **Restore the original** goes back to Zinc's.

To follow Windows' light and dark mode, give a pair:

```toml title="config.toml"
[colors]
theme = "light:Lit Cell Light,dark:Lit Cell"
```

Neovim and other programs that support mode 2031 hear about each switch, so they can change their own colors too.

### Shaders

Shaders are effects drawn over the terminal. Zinc runs GLSL shaders in Shadertoy's form, such as those written for Ghostty, and comes with six, which you use by name:

```toml title="config.toml"
[shaders]
files = ["crt", "cursor-trail"]    # run in this order
```

| Shader | What it draws | Animated |
|---|---|---|
| `scanlines` | Soft dark lines and a light vignette | |
| `crt` | An old monitor, with curved glass and a faint flicker | <Yes /> |
| `glow` | A soft light around bright text | |
| `phosphor` | A one-color screen in Lit Cell's green | |
| `cursor-glow` | A halo around the cursor | |
| `cursor-trail` | A streak behind the cursor when it jumps | <Yes /> |

**Edit shaders**, in `Settings > Appearance > Shaders`, lists these and your own, and a click tries one in the preview. To change one of Zinc's, save a copy as `shaders\crt.glsl` next to `config.toml`. The copy takes the place of Zinc's, and its settings are at the top of the file.

A shader that doesn't compile is left out, and a notice says which line is wrong.

## Profiles and shells {#profiles}

A profile is a shell with its own name, folder, font, and colors. Zinc finds the shells on your PC each time it reads your settings, and lists them after your own.

### Your own profiles {#own-profiles}

Each profile is a `[profile.<id>]` section, with an id you choose:

```toml title="config.toml"
[profile.nu]
name = "Nushell"
command = "nu"
working-directory = "~/src"
font.size = 12               # anything in [font], [colors], [terminal], or [shaders]
```

Menus show the name, and everything else uses the id, so you can rename a profile without breaking anything. Without a `command`, a profile runs PowerShell.

New tabs start with `default-profile`, or else the first profile in the menu. `profile-order` sets the menu's order, and dragging profiles in `Settings > Profiles` writes it for you. Both go at the top of the file.

```toml title="config.toml"
default-profile = "wsl:Ubuntu"
profile-order = ["wsl:Ubuntu", "pwsh", "nu"]
```

### Shells Zinc finds {#found-profiles}

| Found | Profile id |
|---|---|
| WSL distros | `wsl:<distro>` |
| PowerShell 7, Windows PowerShell, cmd | `pwsh`, `powershell`, `cmd` |
| Git for Windows | `git-bash` |
| MSYS2 (UCRT64) | `msys2:ucrt64` |
| Visual Studio developer shells | `vs:<instance>:pwsh`, `vs:<instance>:cmd` |
| Hosts in `~/.ssh/config` | `ssh:<host>` |

A `[profile]` section with a found profile's id changes it. `[discover]` turns a source off.

```toml title="config.toml"
[discover]
ssh = false                  # also wsl, powershell, cmd, git-bash, msys2, visual-studio

[profile."wsl:Ubuntu"]
colors.theme = "Ubuntu"

[profile."msys2:ucrt64"]
hidden = true
```

If a shell you changed goes away, Settings keeps your changes and marks the profile as one that can't open.

### Choosing a shell {#choosing-a-shell}

To start Zinc with a particular shell from a shortcut or a launcher, put the shell's command after `zinc.exe`, as in `zinc.exe nu`. Setting `ZINC_SHELL` to a command does the same. Either way, Zinc opens a window running that shell instead of reopening your saved windows.

Programs can tell they're in Zinc from `TERM_PROGRAM=zinc`, and `COLORTERM=truecolor` tells them Zinc shows 24-bit color.

### Environment variables {#environment}

`[environment]` sets variables for every program Zinc starts, and a profile can add its own. `%NAME%` uses a variable's current value, and an empty value removes a variable.

```toml title="config.toml"
[environment]
PATH = '%PATH%;C:\tools'     # single quotes, so \t stays as typed
NO_COLOR = ""

[profile.pwsh.environment]
POWERSHELL_TELEMETRY_OPTOUT = "1"
```

WSL passes on only the variables that `WSLENV` names, so add yours to `WSLENV` to use them in Linux.

## Workspaces, panes, and tabs {#workspaces}

A window holds workspaces, along the top or in a sidebar. Each workspace splits into panes, and each pane holds one or more tabs, each a terminal. New tabs open in the focused pane, with the profile of the tab you're in.

If you'd rather have one terminal per pane, turn off "Tabs inside panes" in `Settings > Layout`. New tabs then open as workspaces.

### New workspaces {#new-workspace}

<kbd>Ctrl+Alt+T</kbd> or the **+** opens a page for picking a profile, a folder, and a layout, from one pane up to a grid of four. Enter starts it, and Enter alone starts your default profile in its usual folder. The page also lists the workspaces you closed lately, to reopen with a click.

A workspace started in a folder keeps it, so its new tabs start there too. To skip the page, clear **Show this page for new workspaces** at its bottom.

### Splitting and moving {#panes}

Split with <kbd>Alt+Shift+Plus</kbd> and <kbd>Alt+Shift+Minus</kbd>, move between panes with <kbd>Alt</kbd> and an arrow, and resize with <kbd>Alt+Shift</kbd> and an arrow. Double-click a pane's header to fill the workspace with it, and again to bring the others back.

Tabs, panes, and workspaces move by dragging. Drag a pane by the empty part of its header. Where you drop it decides what happens:

- **On a pane's edge**, it becomes a new pane on that side.
- **On a pane's middle**, it joins that pane's tabs.
- **On the workspace tabs**, it becomes a workspace of its own.
- **Outside every Zinc window**, it opens in a new window.

Right-click a workspace to rename it, give it a color, an icon, or a folder, or move it to a window of its own. With workspaces in a sidebar, <kbd>Ctrl+Shift+B</kbd> narrows the sidebar to a rail of icons, then hides it until you point at the window's left edge.

### Reopening where you left off {#reopening}

Zinc saves your windows as you go, with their workspaces, splits, and tabs, and reopens them the next time it starts. Each tab gets a fresh shell in the folder it was in. What the terminals showed isn't kept.

**Reopen closed workspace** and **Reopen closed window**, in the command palette, bring back what you closed lately. To start with a new window every time instead, set "Reopen windows" in `Settings > Layout` to "Start fresh".

A tab knows its folder when its shell reports it, which shells with [shell integration](#shell-integration) do for you. Other shells can send the report from their prompt:

```sh title="Your prompt"
printf '\e]7;file://%s%s\e\\' "$HOSTNAME" "$PWD"
```

Without a report, a tab reopens in the folder it started in.

## Shell integration

Shells can mark where each prompt, command, and output starts, and how each command ended. Zinc uses the marks to:

- Jump between prompts with <kbd>Ctrl+Shift+↑</kbd> and <kbd>Ctrl+Shift+↓</kbd>.
- Copy or select a command's output, from the command palette or the right-click menu.
- Show a red bar beside a failed command, and a mark on the scrollbar at each prompt.
- Mark a tab when a long command finishes out of view, in green when it succeeded or red when it failed.
- Ask before closing a tab while a command is still running in it.
- Reopen tabs in the folder they were in.

### Which shells

Most shells need nothing from you. Your startup files run as usual, and Zinc's script runs after them without changing anything you see.

| Shell | Set up | Exit codes |
|---|---|---|
| PowerShell 7 and Windows PowerShell | Automatic | <Yes /> |
| bash, in WSL, Git Bash and MSYS2 | Automatic | <Yes /> |
| zsh | Automatic | <Yes /> |
| elvish, OSH | Automatic | <Yes /> |
| cmd | Automatic | <Partly>With Clink</Partly> |
| fish, nushell | Built into the shell | <Yes /> |

<Note title="Your prompt already sends marks?">
Then Zinc leaves them to it, whether that's powerlevel10k's own integration or one you wrote, and adds only what's missing.
</Note>

### Turning it off

To start shells exactly as they'd start anywhere else, turn it off for every profile, or for one:

```toml title="config.toml"
[terminal]
shell-integration = "off"
```

If your startup files hand over to something else, such as tmux or `exec` into another shell, the marks don't follow. The scripts in the `ShellIntegration` folder next to `zinc.exe` show what to send from there.

### Not reached yet {#not-yet}

- bash in WSL, when your startup files replace `PROMPT_COMMAND` instead of adding to it. Git Bash is fine.
- elvish inside WSL, YSH, and xonsh.
- Exit codes in cmd without Clink.

## The zn CLI {#zn}

`zn` opens, arranges, and closes windows, workspaces, panes, and terminals in the running Zinc. It can also type into a terminal and read what it shows, so scripts can set up your work for you.

### Turn it on {#turn-on}

Remote control is off until you turn it on, in `Settings > Terminal > Command line` or in your config:

```toml title="config.toml"
[cli]
remote-control = true
```

Inside Zinc, `zn` is already on your `PATH`. To use it from other terminals too, turn on **Use zn in other terminals**.

### Examples

```sh title="Any shell" copy="the zn examples"
zn list                                     # everything open, with ids
zn pane split right -- htop                 # a pane beside this one, running htop
zn terminal new --pane 4 --profile wsl:Fedora
zn workspace new --name api --cwd .         # a workspace in this folder
zn terminal send --terminal 5 ":w\r"        # types into terminal 5 (\r is Enter)
zn terminal read --terminal 7 --lines 20    # the last 20 lines of terminal 7
zn workspace color teal                     # this workspace's color
zn action "zoom-in"                         # any action, by its name
```

### Commands

Commands are `zn <thing> <verb>`.

| Thing | Verbs |
|---|---|
| `window` | list, new, focus, close |
| `workspace` | list, new, focus, close, rename, color, icon, move |
| `pane` | list, split, focus, close |
| `terminal` | list, new, send, read, title, focus, move, close |

Run inside Zinc, a command acts on the terminal it runs in, and on that terminal's pane, workspace, and window. `--terminal`, `--pane`, `--workspace`, and `--window` aim elsewhere, using ids from `zn list`. Add `--json` for output scripts can read, and run `zn <thing> --help` for the rest.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | Done |
| `1` | Refused or failed |
| `2` | Wrong usage |
| `3` | Zinc isn't running |
| `4` | Remote control is off |
